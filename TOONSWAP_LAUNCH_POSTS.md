## Recommended publishing order

Do not publish everything at the same minute. Use this simple sequence:

1. X thread first.
2. Instagram carousel later the same day.
3. WhatsApp Status and selected personal groups after the public posts are live.
4. Facebook and LinkedIn on the same or following day.
5. Reddit after reading the target community rules.
6. DEV article after the shorter posts have collected a few useful questions.

Post when you can stay available to answer early comments. A real reply is more
useful than trying to guess a perfect posting hour.

Most creative tools become more powerful by adding controls. That can also make the first session intimidating.

I started ToonSwap with a different question:

> Could an animated-story workflow be understandable before a creator learns timelines, tracks, render settings, or prompt engineering?

The current result is an early product preview built around a guided sequence: choose a world, pick a cast, direct the voice, describe the scenes, and review the plan.

![Eight illustrated ToonSwap characters from different story worlds](PASTE_DEV_CHARACTER_SHOWCASE_URL_HERE)

## Start with visible choices

A blank prompt can be surprisingly demanding. It asks a new creator to invent the world, character, tone, action, camera, voice, and format at the same time.

ToonSwap starts with illustrated choices instead. The current launch set contains 24 finished character illustrations. A larger structured catalogue exists, but unfinished records remain labelled as production blueprints rather than being presented as completed art.

That distinction matters. A big number is not useful if the interface quietly fills the gap with repeated placeholders.

## Make the workflow explain itself

The guided flow has three broad moments.

![Step one: choose a world and illustrated cast](PASTE_DEV_FLOW_01_URL_HERE)

First, the creator picks a world and cast. The goal is to create momentum with a visual decision rather than an empty text box.

![Step two: describe scenes and choose voice direction](PASTE_DEV_FLOW_02_URL_HERE)

Second, the creator describes what happens and chooses language, feeling, and performance direction. Advanced controls should appear only when they are useful.

![Step three: arrange, tune, and preview the planned story](PASTE_DEV_FLOW_03_URL_HERE)

Third, the creator reviews the scene order and adjusts the plan. The product should always make the next action obvious.

## Treat faces and voices as sensitive data

A selfie or voice recording is not an ordinary decorative upload.

The product foundation therefore uses protected accounts, private media references, short-lived signed access, consent records, retention controls, and moderation boundaries. It also rejects requests to imitate real performers or copy protected characters.

These safeguards are not a footer slogan. They affect storage, provider calls, queue design, moderation, and what the interface is allowed to promise.

## The current stack

The frontend uses Vue 3, the Composition API, Pinia, Tailwind CSS, scoped SCSS, and Vite.

The backend uses NestJS, TypeScript, Prisma, PostgreSQL, BullMQ, Redis, and S3-compatible object storage. Provider-specific visual and voice work belongs behind adapters and queued workers instead of inside controllers.

Authentication uses opaque server-side sessions with HttpOnly cookies, CSRF protection, Turnstile verification, and role-protected administration.
